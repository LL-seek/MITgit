# 旧工程缺陷与迁移决策

版本：`defect-register/2026-08-28`  
状态含义：本表冻结处置方向；除 D-001 外尚未在新工程实施。阶段 0 的“已决策”不能被解释为缺陷已经修复。

## 1. 责任角色

| 代码 | 可问责职责 |
|---|---|
| FW | 固件迁移负责人：设计/实现、静态与单元测试、构建证据 |
| HW | 板卡负责人：BOM、原理图/PCB/装配、连续性与电气安全 |
| QA | 台架验证负责人：测试方案、仪器原始数据、回归判定 |
| PM | 产品/系统负责人：范围、兼容破坏、暂缓功能的批准 |

当前没有提供人员姓名，因此先以不可空缺的责任角色分配；关闭相应硬件/发布门禁前，项目方须把角色映射到具体人员并在测试记录签名。

## 4. 变更控制

1. 新发现的问题按下一个 D-ID 追加，不回收或重解释旧 ID。
2. 修改“最终决策”需要记录日期、理由、批准角色和受影响合同。
3. 状态只能由对应验证证据推进；代码合并或口头确认不能代替仪器/测试记录。
4. “延后”项必须在目标构建中显式隔离，不能保留死代码后声称不在范围内。
5. “需要实测”项在实测前一律按更保守的安全状态处理。
