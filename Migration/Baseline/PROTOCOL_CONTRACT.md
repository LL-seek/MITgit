# CAN/MIT 协议兼容合同（阶段 0）

版本：`legacy-can-contract/2026-08-28`  
证据源：`main.cpp`、`CAN/CAN_com.cpp`、`Config/user_config.h`、旧 mbed CAN 实现。  
原则：本文件冻结**外部可观察行为**；同时明确旧实现中必须修复的输入校验和 ISR 结构问题。

## 1. CAN 链路合同

| 项 | 合同值 |
|---|---|
| 控制器/引脚 | CAN1，PB8=RX，PB9=TX |
| 帧格式 | 11-bit Standard Data Frame |
| 标称速率 | 1,000,000 bit/s |
| 接收仲裁 ID | `CAN_ID`，有效配置范围 0～127，默认 1 |
| 反馈仲裁 ID | `CAN_MASTER`，兼容范围 0～255，默认 0 |
| 命令 DLC | 8 |
| 反馈 DLC | 6 |
| 字节序 | 多字节位域按网络顺序（高位字节先发） |
| 接收过滤 | 精确匹配当前 `CAN_ID`，mask `0x7FF` |

迁移实现必须先验证：标准数据帧、ID 匹配、DLC=8。错误类型、错误 DLC 或错误 ID 不得解包、不得刷新超时、不得触发参数保存，也不发送反馈。旧实现没有检查 DLC 并在回调中直接打印，这是有意修复的安全偏差（D-021/D-024），不属于协议破坏。

## 2. 普通 MIT 命令帧

### 2.1 物理量范围与量化

| 字段 | 范围 | 位数 | 单位 |
|---|---:|---:|---|
| `p_des` | -12.5 ～ +12.5 | 16 | rad |
| `v_des` | -10.0 ～ +10.0 | 12 | rad/s |
| `kp` | 0.0 ～ 500.0 | 12 | 旧接口增益单位 |
| `kd` | 0.0 ～ 5.0 | 12 | 旧接口增益单位 |
| `t_ff` | -36.0 ～ +36.0 | 12 | N·m（输出侧合同） |

解码公式：

```text
x = raw * (x_max - x_min) / (2^bits - 1) + x_min
```

兼容编码采用旧实现的截断语义：

```text
raw = trunc((x - x_min) * (2^bits - 1) / (x_max - x_min))
```

发送方应先把物理量限幅到合同范围。接收端的位域天然不会超出上述 raw 范围。

### 2.2 8 字节布局

| Byte | 位定义 |
|---:|---|
| 0 | `p[15:8]` |
| 1 | `p[7:0]` |
| 2 | `v[11:4]` |
| 3 | `v[3:0] << 4` `OR` `kp[11:8]` |
| 4 | `kp[7:0]` |
| 5 | `kd[11:4]` |
| 6 | `kd[3:0] << 4` `OR` `t[11:8]` |
| 7 | `t[7:0]` |

普通帧仅在 `MOTOR_MODE` 中发布为控制命令。在 REST/SETUP 等状态收到语法有效的普通帧时，旧行为是不更新控制目标但仍发送一帧当前反馈；迁移实现保持这一外部行为。

### 2.3 十六进制向量

| 输入载荷 | 解码期望 |
|---|---|
| `00 00 00 00 00 00 00 00` | `p=-12.5, v=-10, kp=0, kd=0, t=-36` |
| `7F FF 7F F0 00 00 07 FF` | 量化零点：`p≈-0.000190738, v≈-0.00244200, kp=0, kd=0, t≈-0.00879121` |
| `FF FF FF FF FF FF FF FF` | `p=+12.5, v=+10, kp=500, kd=5, t=+36` |

量化是非对称奇数满量程，零点不能被这些位宽精确表示；测试不得把中点误写为严格 0。

## 3. 反馈帧

反馈的仲裁 ID 为**当前** `CAN_MASTER`，DLC=6。物理量在编码前限幅。

| Byte | 位定义 |
|---:|---|
| 0 | 当前 `CAN_ID` 的低 8 位 |
| 1 | `position[15:8]` |
| 2 | `position[7:0]` |
| 3 | `velocity[11:4]` |
| 4 | `velocity[3:0] << 4` `OR` `torque[11:8]` |
| 5 | `torque[7:0]` |

反馈量及范围：

- position：`controller.theta_mech`，-12.5～+12.5 rad，16 bit；
- velocity：`controller.dtheta_mech`，-10～+10 rad/s，12 bit；
- torque：`controller.i_q_filt * KT_OUT`，其中旧配置 `KT_OUT=3.15`，-36～+36 N·m，12 bit。

默认 `CAN_ID=1`、`CAN_MASTER=0` 时的向量：

| 状态输入 | 仲裁 ID / DLC / 载荷 |
|---|---|
| `p=-12.5, v=-10, t=-36` | `0x000 / 6 / 01 00 00 00 00 00` |
| `p=0, v=0, t=0` | `0x000 / 6 / 01 7F FF 7F F7 FF`（解码为上节所列量化零点） |
| `p=+12.5, v=+10, t=+36` | `0x000 / 6 / 01 FF FF FF FF FF` |

每个语法有效、ID 匹配的命令帧处理后发送一次反馈，包括特殊帧。若帧改变了本机 ID 或主机 ID，反馈使用更新后的值：改变本机 ID 后 byte 0 是新 ID；改变主机 ID 后反馈仲裁 ID 是新主机 ID。

## 4. 特殊帧

匹配顺序必须保持下表顺序，所有帧 DLC 均为 8。

| 名称 | 载荷 | 状态/副作用 | 反馈 |
|---|---|---|---|
| Enter Motor | `FF FF FF FF FF FF FF FC` | 请求进入 `MOTOR_MODE` | 立即发送当前反馈 |
| Exit Motor | `FF FF FF FF FF FF FF FD` | 进入 `REST_MODE`，置 `state_change=1`，LED 关闭 | 立即发送当前反馈 |
| Zero Position | `FF FF FF FF FF FF FF FE` | 产生零位保存请求 | 立即反馈；实际保存必须在安全状态执行 |
| Change CAN ID | `FF FF FF FF FF FF nn FA` | `nn` 必须 0～127；更新过滤器并请求持久化 | 用新 `CAN_ID` 反馈 |
| Change Master ID | `FF FF FF FF FF FF nn 01` | `nn` 兼容 0～255；请求持久化 | 用新 `CAN_MASTER` 作为仲裁 ID 反馈 |

Change CAN/Master 帧只有 byte 0～5 固定为 `FF`；byte 6 是参数，不要求为 `FF`。未知特殊尾码在 `MOTOR_MODE` 中会与普通 MIT 帧同形，因此协议没有额外“特殊命令命名空间”。新增特殊命令必须另行版本化，不能擅自占用现有 8 字节组合。

旧代码在 `FD`/`FE` 条件中把两个布尔项用乘法连接；对 0/1 比较结果目前与逻辑 AND 等价。迁移实现改为清晰的逐字节比较，不复制表达式缺陷。

## 5. CAN 超时合同

| 项 | 合同 |
|---|---|
| 配置字段 | `CAN_TIMEOUT`，单位为 40 kHz 控制周期 |
| 默认值 | 0，禁用 |
| CLI 展示范围 | 0～100,000 cycles |
| 刷新条件 | 通过类型/ID/DLC 校验的匹配帧；普通帧和已识别特殊帧均刷新 |
| 计数条件 | `MOTOR_MODE` 的正常快速循环，每周期加 1 |
| 旧触发判定 | 在递增前检查严格 `timeout > CAN_TIMEOUT` |
| 超时动作 | 将 `i_d_ref`、`i_q_ref`、`kp`、`kd`、`t_ff` 清零；保持状态并继续零目标控制；同时产生诊断事件 |

例：40 kHz 下，1,000 cycles 标称 25 ms，40,000 cycles 标称 1 s，100,000 cycles 标称 2.5 s。由于旧实现采用严格大于并在检查后递增，边界存在一个控制周期级的相位/偏移；兼容测试必须按计数序列验证，不能仅用墙钟近似。

迁移实现可以用单调时间戳代替易溢出的自增整数，但必须保持配置单位和边界测试的可观察结果。错误 DLC/帧型不能再“喂狗”。

## 6. 并发与安全边界

这些是协议实现合同的一部分：

1. CAN RX ISR 只完成硬件取帧、时间戳和固定大小队列投递；不 `printf`、不解包控制逻辑、不写 Flash、不直接切 PWM。
2. App 任务按本文件顺序解析特殊帧/普通帧并生成事件。
3. Zero、Change CAN ID 和 Change Master ID 只能**请求**保存；保存状态机必须先退出 MOTOR、进入 COAST、停止快速功率输出，再擦写并回读校验。
4. 队列满、发送邮箱满、非法帧和超时都要有可读取诊断计数；不得在 ISR 阻塞等待。
5. 所有样例向量在纯 C 协议单元测试和 HIL CAN 回环中各验证一次。

## 7. 验收测试最小集合

- 三个普通命令向量逐字段解码；三个反馈向量逐字节编码；
- 五类特殊帧的状态、副作用、响应 ID 和 byte 0；
- ID 边界 0/127、Master 边界 0/255，以及越界/错误 DLC/扩展帧/远程帧拒绝；
- REST 中普通帧不改变目标但返回反馈；MOTOR 中普通帧更新目标；
- `CAN_TIMEOUT=0` 永不触发；1、1,000 和 100,000 的边界序列；
- 非法帧不刷新超时；合法特殊帧刷新超时；
- CAN 洪泛与 TX mailbox 满时，40 kHz 快速路径仍满足时限。
